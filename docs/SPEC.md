## 1. 배경과 문제 정의

인스타그램 사진 보너스 모델의 제작 공정은 단순하다: 해외에서 검증된 사진 소재를 골라, 한국인이 멈춰 볼 후킹 문장 한 줄을 얹어 게시하는 것. 그러나 실제로는 매 게시물마다 아래 6단계를 손으로 반복해야 하고, 여기서 시간이 새고 품질이 흔들린다.

1. 소재의 핵심 사실 파악 (사진이 말하는 이야기가 무엇인가)
2. 후킹 문장 작성 (번역체 제거, 규칙 적용, 길이 제한)
3. 이미지 합성 (문장을 사진에 얹는 템플릿 작업)
4. 다국어 버전 제작 (국가별 현지화)
5. 정책·권리 검수 (게시 전 체크)
6. 기록 (무엇을 만들었고, 출처가 어디이며, 성과가 어땠는지)

이 도구는 1~6을 한 화면 흐름으로 묶어, 소재 1건당 제작 시간을 **5분 이내**로 줄이는 것이 목표다. (강의 자료가 주장하는 제작 시간과 같은 목표치)

## 2. 범위

### 만든다 (In scope)
- 소재 등록·관리 (이미지 + 출처·권리 상태 기록)
- 소재 분석 보조 (이미지에서 핵심 사실 1개 추출)
- 후킹 카피 후보 생성·선택·편집 (한국어 원본 + 다국어 현지화)
- 템플릿 기반 이미지 합성·미리보기
- 게시 전 검수 (정책 금지 항목·형식 규칙 자동 체크 + 수동 확인 항목)
- 게시 패키지 내보내기 (이미지 + 캡션 초안 + 기록)
- 제작 이력·성과 기록 (게시 후 조회수 입력欄)

### 만들지 않는다 (Out of scope)
- 웹 앱에서 인스타그램 로그인과 실제 발행을 수행하는 기능. 운영 환경에서는 연결된 운영 에이전트가 검수와 큐 컨펌을 수행하고, 예약 시각에 발행한 뒤 결과를 기록한다(PLAYBOOK §5, 2026-11-12 결정).
- 해외 소재 자동 크롤링/스크래핑 — 권리 확인이 불가능한 수집은 검수 원칙과 충돌한다. 소재는 사용자가 가져와 등록한다 (P2에서 "후보 수집 보조"를 별도 검토)
- 보너스 초대·수익 보장 관련 기능 — Meta 소관이며 도구로 다룰 수 없다
- 다중 사용자·계정 공유 — 1인 사용 전제

## 3. 사용자

- 사용자 1인 (HW). 웹 UI로 접속해 직접 조작한다 (CLI 전제 아님)
- 사용 환경: 로컬 우선. 데이터(소재·기록)는 로컬에 저장된다

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 소재 | 게시물의 바탕이 되는 사진 1장과 그 이야기(핵심 사실). 해외 바이럴 사진이 전형적 |
| 핵심 사실 | 소재에서 뽑은 단 하나의 사실·사건. 카피는 이것만으로 만든다 |
| 후킹 카피 | 사진 위에 얹는 15~28자, 최대 2줄의 문장. 직역이 아닌 "편집"의 결과물 |
| 현지화 | 다른 언어권용 카피를 직역이 아니라 그 언어의 후킹 문장으로 다시 쓰는 것 |
| 게시 패키지 | 완성 이미지(+언어별 버전) + 캡션 초안 + 소재 메타데이터의 묶음 |
| 검수 | 게시 전 정책·권리·형식 체크. 자동 판정 항목과 수동 확인 항목으로 나뉜다 |

## 5. 전체 플로우

```
[소재 등록] → [분석: 핵심 사실 확인] → [카피 생성: 후보 중 선택·편집]
→ [합성: 템플릿 미리보기] → [현지화: 언어별 버전 생성·확인]
→ [검수: 자동 체크 + 수동 확인] → [내보내기: 게시 패키지] → [기록: 게시 후 조회수 입력]
```

- 어느 단계에서든 이전 단계로 돌아갈 수 있다.
- 검수를 통과하지 못한 소재는 내보내기가 잠긴다 (수동 확인 항목은 사용자가 "확인함"으로 명시해야 통과).

## 6. 기능 요구사항

### FR-1 소재 등록·관리
- 이미지 파일 업로드 (JPG/PNG). 등록 시 아래 메타데이터를 함께 기록한다:
  - 출처 (URL 또는 설명) — **필수**. 없으면 등록 불가
  - 권리 상태: `확인됨 / 불명확 / 사용불가` — **필수**. `사용불가`는 이후 단계 진행 불가
  - 넓은 주제 태그 1개 (아래 15개 중 선택): 운동, 동물, 우주, 음식·요리, 건강, 연예·남녀관계, 가족, 직장, 돈·경제, 자동차·교통, 군대·남자공감, 여행, 학교·학창시절, 결혼, 소비·생활
  - 원본 언어/국가 (선택)
- 소재 목록: 상태별 필터 (등록됨 / 제작중 / 검수대기 / 완성 / 게시완료), 주제별 필터
- 소재 상태는 플로우 진행에 따라 자동 전이된다

### FR-2 소재 분석 보조
- 등록된 이미지를 비전 모델로 분석해 **핵심 사실 후보 1~3개**를 문장으로 제시한다
- 사용자는 후보를 선택하거나 직접 수정·입력한다. **핵심 사실이 확정되지 않으면 카피 생성으로 넘어갈 수 없다**
- 분석 결과에는 "사진에 이미 보이는 정보" 목록도 함께 제시한다 (카피에서 지워야 할 정보 — FR-3 규칙 R2의 재료)

### FR-3 후킹 카피 생성 (핵심 기능)
- 입력: 확정된 핵심 사실 + 주제 태그 + 톤 옵션 (유머 강도: 없음/한 스푼)
- 출력: 카피 후보 **5개**, 각 후보에 적용된 변환 포인트를 한 줄로 표시 (예: "결과 앞배치", "숫자 구체화")
- 생성 규칙 (시크릿노트 후킹 공식의 규칙화):
  - R1 핵심 사실 하나만 남긴다. 부연·배경 설명 금지
  - R2 사진이 이미 보여주는 정보는 카피에 넣지 않는다 (FR-2의 목록 활용)
  - R3 기사체·번역체 금지, 한국인이 실제 쓰는 구어체 단어만 사용
  - R4 조사·수식어를 걷어낸다. 빈 수식어("매우 놀라운") 대신 구체적 사건·수치·결과로 쓴다
  - R5 **15~28자, 최대 2줄**. 가장 강한 결과·반전·유머를 문장 앞에 배치한다
  - R6 유머는 옵션 켤 때만 한 스푼. 사실 왜곡은 유머로도 금지
- 형식 검증은 자동이다: 글자 수·줄 수 초과 후보는 생성 즉시 표시하고, 확정 시에는 제한을 만족해야 한다
- 사용자는 후보 선택 후 직접 편집할 수 있다. 편집본도 같은 형식 검증을 받는다

### FR-4 이미지 합성
- 템플릿 1종으로 시작 (P0): 사진 하단 그라데이션 영역 + 굵은 고딕 텍스트 (흰색 본문 + 핵심 단어 1곳 색상 강조), 강의 사례 이미지와 같은 계열의 지면 구성
- 출력 규격: 1080×1350 (4:5, 인스타 피드 권장) 기본. 원본 비율 유지 옵션 제공
- 카피 줄바꿈은 자동 + 수동 조정 가능. 강조 단어는 사용자가 지정 (기본값: 모델 제안)
- 실시간 미리보기. 텍스트가 사진의 주요 피사체를 가리면 경고 표시 (단순 겹침 감지 수준)

### FR-5 다국어 현지화
- 확정한 한국어 카피와 핵심 사실을 바탕으로 영어·일본어·스페인어·포르투갈어·인도네시아어·튀르키예어 버전을 만든다. 사용자는 대상 언어를 선택하거나 선택한 언어 전체를 일괄 생성한다.

### FR-6 게시 전 검수
- 한국어 후킹 문장과 캐러셀 본문의 참여 유도·단정적 의학 표현·빈 수식어를 검사하고 발견 내용을 표시한다.
- 운영자가 출처와 권리, 사실관계, 유해 표현, 반복·저품질 여부를 각각 확인한다. 사용불가 소재는 진행을 차단한다.
- 현재 버전의 이미지 전체가 존재하고 자동·수동 검수를 통과해야 완성으로 전환한다. 카피, 슬라이드, 합성본이 바뀌면 다시 검수한다.

### FR-7 게시 패키지
- 검수한 이미지, 언어별 합성본, 캡션 초안과 출처·권리·핵심 사실 기록을 ZIP으로 내려받는다. 캐러셀 파일은 슬라이드 순서를 보존한다.

### FR-8 보드·배치·성과
- 보드에서 소재를 선택해 카피 생성, 합성, 현지화를 일괄 실행한다. 실패는 소재별로 표시하고 나머지 작업을 계속한다.
- 게시 결과와 조회수를 기록하고 주제별 건수·총합·평균 및 상위 게시물을 확인한다.

### FR-9 소싱
- 주제별 검색어를 제안하고 후보 URL과 메모를 저장한다. 후보를 채택하거나 버릴 수 있고 채택 후에도 실제 이미지와 권리 확인은 등록 과정에서 수행한다.

### FR-10 게시 큐
- 완성된 소재만 등록한다. 대기·컨펌 중 중복 등록을 차단하고 게시 순서·캡션·예약 시각을 운영자에게 제공한다. 자동 발행 작업은 컨펌됨 상태이며 예약 시각이 지난 항목만 가져간다. 수동 게시를 포함한 결과는 게시완료·실패·취소로 기록한다.
- 채널 일정 생성기는 채널별 현지 날짜·시간대·시간 구간·건수를 따르고 계정 간 최소 10분 간격을 지킨다. 배정할 수 없는 요청은 오류로 돌려준다.

### FR-11 이미지 재생성
- 원본 스토리 URL과 장면 프롬프트를 입력해 이미지를 생성한다. 소재에 원본 출처·AI 재생성 여부·프롬프트를 보존하고 일반 소재와 같은 게시 전 검수를 거친다.

### FR-12 스토리 캐러셀 (2026-10-21 추가, HW 지적 + 운영 판단)
- 배경: 무료 전자책은 "한 장짜리 후킹 이미지"와 "캐러셀형 정리 이미지"를 모두 유효 형식으로 명시한다 (전자책 p.15). 구체 구성법은 유료 강의 영역이라 자료에 없으므로, 운영 형식은 운영자가 정한다: **스토리형 캐러셀을 주력**으로 한다 (넘겨보기·저장·체류가 보너스 모델의 핵심 변수이기 때문).
- 구성: 2~12장, **기본 8~12장** (HW 2026-10-21: 10장 안팎이어야 이야기가 성립하고 끝까지 넘겨본다). 1장 = 후킹 (확정 카피와 동일 문장, 강조 표시 유지), 이후 장 = 이야기 전개·결말을 장당 한 비트씩 (최대 2줄, 공백 제외 45자 이내, 작은 폰트로 합성).
- 각 슬라이드는 이미지 1장 + 문장 1개. 슬라이드 이미지는 AI 재생성(FR-11 경로)으로 장면별로 만들 수 있고, 1장은 소재 원본 이미지를 기본값으로 쓴다.
- 게이트: 모든 슬라이드 이미지가 있어야 합성 가능. 합성 결과는 검수·내보내기·게시 큐에 순서가 있는 파일 목록으로 흐른다. 큐 항목은 files(게시 파일 순서)와 scheduled_for(18:00~21:00 랜덤 추첨)를 가진다.
- 단일 이미지 게시(슬라이드 없음)도 기존대로 가능하다.


## 7. 제품 인수 조건

| 흐름 | 운영자가 확인할 결과 | 검증 경로 |
|---|---|---|
| 키 없는 첫 실행 | 샘플 1건과 스텁 표시가 뜨며 같은 데이터 폴더에서 재실행해도 중복 생성되지 않는다 | `make demo`, 제작 탭 |
| 제작·현지화 | 사실을 확정하면 후보를 생성하고 선택·편집한 문구로 합성한다. 선택한 언어별 결과를 확인할 수 있다 | 제작 탭, 서비스·렌더 테스트 |
| 복수 소재 | 상태·주제 필터, 소재별 검수 체크, 보드의 작업별 성공·실패를 확인한다 | 제작·보드 탭 |
| 캐러셀 검수 | 1장은 후킹과 같고, 누락된 장이나 본문 금지 문구가 있으면 완성·내보내기·큐 등록을 차단한다 | 캐러셀·검수 테스트 |
| 내보내기·게시 기록 | ZIP에 순서대로 이미지와 출처가 들어간다. 큐 등록 후 편집해도 대기 파일은 승인된 버전을 가리킨다. 게시 결과·조회수가 성과 화면에 반영된다 | 큐·서비스 테스트, ZIP 열기 |
| 운영 사전점검 | 채널 파일, 렌더 환경과 게시 도구를 점검한다. 게시 내역 조회 실패 시 게시 호출을 중단한다 | `scripts/preflight.py`, `scripts/safe_publish.py` |

### Muse 운영 인수

운영 환경은 Meta Muse의 지속형 Linux VM이다. Muse 에이전트가 운영자의 역할을 맡고, Storyforge는 소재·검수·파일·게시 큐를 관리한다. Muse의 내부 실행 구성요소 이름은 Hatch이며 운영 스크립트는 VM의 Instagram 커넥터 CLI를 사용한다. 모델 서버 주소와 모델명은 제작 환경에서 별도로 설정한다. [Muse 실행 환경](https://muse.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)

1. 운영 에이전트는 채널별 출처·권리와 원본 이야기를 확인한 뒤 소재를 등록한다. 프리뷰와 검수 결과를 확인한 건만 큐에 넣고 컨펌한다.
2. 예약 작업은 `check_due.py`가 반환한 `due_confirmed`를 처리한다. 조회 실패(종료 코드 2)는 당일 대기 건수 0으로 기록할 수 없다.
3. `safe_publish.py`는 최근 20건을 조회한 뒤 컨펌한 순서대로 파일을 전달한다. 정상 발행(0)과 기존 게시물 발견(2)은 해당 게시물 ID·URL·시각을 기록한다. 실패(1)는 계정 상태를 확인한 뒤 처리한다. 커넥터가 추가 승인을 기다리거나 발행 결과가 불분명해 `needs_reconciliation`이 반환되면 운영 에이전트는 큐를 `확인필요`로 기록한다. 해당 항목은 자동 발행 대상에서 빠진다. 이전 승인 요청과 실제 계정 내역을 확인한 뒤 결과를 확정한다.
4. 저장소 인수에서는 실제 프로세스 경계에 CLI 대역을 두고 성공, 기존 게시물, 결과가 불분명한 발행을 검증한다. 배포 인수에서는 Muse VM의 채널 설정·폰트·커넥터를 사전점검하고, 샘플의 검수·큐 ID와 게시 결과를 연결한 기록을 확인한다.

소재당 5분 목표는 실제 모델 대기 시간과 운영자 검수 시간을 포함해 등록부터 ZIP 생성까지 측정한다. 키 없는 데모는 동작 검증에 사용하며, 실모델의 사실 보존·카피 품질·소요 시간은 운영 인수에서 측정한다.
